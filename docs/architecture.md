# Архитектура DeCo

## Слои системы

1. **Слой идентичности (Identity Layer)**
   - Soulbound-токены (SBT) для верификации участников
   - 1 человек = 1 голос
   - Приватность: хранится минимум данных, верификация — через доверенные ячейки

2. **Слой учёта (Ledger Layer)**
   - Смарт-контракты в сети TON
   - Паевой токен как свидетельство вклада (не спекулятивный актив)
   - Прозрачная цифровая амбарная книга

3. **Слой обмена (Exchange Layer)**
   - P2P-обмен ресурсами и услугами
   - Ресурсный баланс вместо рыночной стоимости
   - Локальные правила внутри ячеек

4. **Слой управления (Governance Layer)**
   - DAO с голосованием по SBT
   - Неизменяемое ядро + обновляемые модули
   - Процедура споров и форков

5. **Слой интеграции (Integration Layer)**
   - API-шлюзы
   - Локальные ноды
   - Интеграция с 1С и оффлайн-учётом

## Принципы

- **Неизменяемое ядро**: базовые правила не меняются без форка.
- **Обновляемые модули**: параметры экономики и интеграций — через DAO.
- **Отсутствие единой точки отказа**: локальные ноды, распределённый учёт.
- **Минимум доверия**: криптография вместо посредников.

## Что нужно описать в следующих версиях

- Схема эмиссии паевого токена
- Процедура верификации SBT
- Механизм разрешения споров
- Модель финансирования нод
- Стандарты API-шлюзов
